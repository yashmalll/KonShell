# KonShell — как устроено

Подробности для тех, кто хочет разобраться в коде или поменять поведение: модули, сервисы, IPC, решения и замеры.
Установка и обзор возможностей — в [README](../README.md).

## Структура

- `config/`: синглтоны `Theme` (токены из `~/.local/state/konshell/palette.json`) и `Settings` (`~/.config/konshell/settings.json`); `color.js` — сборка токенов и проверка контраста; `fallback-palette.js` — резервная палитра
- `scripts/generate-palette.sh`: запуск matugen с кэшем и обходом через ffmpeg
- `install.sh`: установка и удаление (пакеты, ссылки, niri, перекраска приложений)
- `niri/konshell.kdl`: автозапуск, клавиши и правила для niri (подключается к config.kdl через include)
- `scripts/install-theme-hooks.sh`: подключение файлов цветов к kitty, niri, GTK, Zed и Qt
- `services/ThemeExport.qml`, `templates/`: перекраска приложений под палитру
- `scripts/make-thumbnails.sh`: миниатюры обоев в `~/.cache/konshell/thumbnails` (один раз, потом только новые)
- `tools/check-palette.js`: проверка палитры по WCAG вне оболочки
- `services/`: данные, например `Niri` (состояние и действия через IPC niri); `Cursor` — единый курсор для niri, GTK и XWayland
- `widgets/`: переиспользуемые элементы отображения
- `modules/`: части оболочки — панель, док, лаунчер, уведомления, OSD, центр управления, обои, блокировка, polkit, окно настроек

## IPC

```sh
qs -c konshell ipc show                              # все цели и функции
qs -c konshell ipc call launcher toggle              # лаунчер
qs -c konshell ipc call notifications toggleCenter   # история уведомлений
qs -c konshell ipc call notifications toggleDnd      # «не беспокоить»
qs -c konshell ipc call notifications clear          # очистить историю
qs -c konshell ipc call audio increase|decrease|toggleMute|toggleMicMute
qs -c konshell ipc call brightness increase|decrease
qs -c konshell ipc call controlCenter toggle
qs -c konshell ipc call controlCenter open wifi|bluetooth|audio
qs -c konshell ipc call settings open appearance|interface|bar|clock|notes|dock|…   # id разделов — config/settings-schema.js
qs -c konshell ipc call dashboard toggle             # календарь, плеер, заметки (как клик по часам)
qs -c konshell ipc call dashboard note               # сразу в поле новой заметки
qs -c konshell ipc call sidebar toggle               # боковая панель: заметки, скриншот, запись
qs -c konshell ipc call sidebar note                 # окно новой заметки
qs -c konshell ipc call system stats                 # процессор, память, температура, диск (JSON)
qs -c konshell ipc call system toggleCaffeine        # «Не засыпать» вкл/выкл
qs -c konshell ipc call clipboard toggle             # история буфера обмена
qs -c konshell ipc call recorder toggle|region|stop   # запись экрана: весь экран, область, стоп
qs -c konshell ipc call recorder screenshot          # инструмент снимков niri
qs -c konshell ipc call session toggle               # меню выключения
qs -c konshell ipc call session request poweroff     # lock|suspend|logout|reboot|poweroff, с отсчётом
qs -c konshell ipc call dock toggle                  # показать или спрятать док
qs -c konshell ipc call dock pin|unpin <id .desktop>  # закрепить, открепить
qs -c konshell ipc call wallpaper set ~/Pictures/Wallpapers/картинка.jpg
qs -c konshell ipc call wallpaper next|prev|get|rescan
qs -c konshell ipc call theme status                 # диагностика палитры
qs -c konshell ipc call shell memory                 # память оболочки: RSS, PSS, своя (МБ)
qs -c konshell ipc call theme toggleMode|regenerate
qs -c konshell ipc call theme setMode light|dark
qs -c konshell ipc call theme setScheme vibrant
```

## Монитор системы и «Не засыпать»

`services/SystemStats.qml` читает `/proc/stat`, `/proc/meminfo`, датчик температуры процессора (`x86_pkg_temp`, у AMD — `k10temp` через hwmon) и `df` по всем смонтированным разделам (корень, `/home`, `/boot` и другие; подкачка — из `/proc/meminfo`) — раз в 2 секунды (разделы — раз в 30) и только пока данные видны: открыта панель под часами (карточка «Система») или центр управления (плитка «Система»), либо на панели стоит виджет «Монитор системы» (`sysmon`, добавляется в «Настройки KonShell» → «Панель» → «Расположение виджетов»). Высокая нагрузка (процессор > 85 %, память > 90 %, температура ≥ 85 °C) — цветом предупреждения.

«Не засыпать» (`services/Caffeine.qml`) — плитка в центре управления: пока включено, панель держит Wayland idle-inhibit, экран не блокируется и не гаснет по простою. Клик по плитке: выключено → пока не выключите → 1 ч → 2 ч → выключено; на время — выключится само.

## Запись экрана и скриншоты

`services/ScreenRecorder.qml` на `wf-recorder` и `slurp` (`sudo pacman -S wf-recorder slurp`). В боковой панели (см. ниже) две плитки:

- «Запись»: клик — записать монитор с фокусом целиком, стрелка → — выбрать область мышью (slurp, Esc — отмена); во время записи клик по плитке останавливает. Перед стартом пауза 0,4 с — панель успевает закрыться и не попадает в кадр.
- «Скриншот» — встроенный инструмент снимков niri (область, окно или экран; сохраняет в «Изображения/Снимки экрана» и копирует).

Во время записи в панели — красная мигающая точка и время, клик по ней останавливает запись. Готовый файл — `Видео/Записи экрана/Запись <дата время>.mp4` (папка меняется в настройках), уведомление с кнопками «Открыть» и «Показать в папке». Видео — H.264, кодирует видеокарта (VAAPI, почти без нагрузки на процессор); если не вышло — запись сама перезапускается с программным `libx264`. Звук — компьютера (по умолчанию), микрофон или без звука: «Настройки KonShell» → «Запись экрана».

## История буфера обмена

`modules/clipboard/` и `services/Clipboard.qml` на `cliphist` и `wl-clipboard` (`sudo pacman -S cliphist wl-clipboard`). Оболочка сама держит два наблюдателя `wl-paste --watch cliphist store` — для текста и для картинок — и перезапускает их, если они завершились; отдельно в автозапуск их добавлять не нужно. Записи, помеченные менеджерами паролей как секретные, cliphist не сохраняет.

Окно в стиле лаунчера: поиск по тексту, миниатюры картинок, ↑/↓ — выбор, Enter или клик — скопировать и закрыть, Delete — удалить запись, «Очистить» (два нажатия) — стереть всё. Настройки — «Настройки KonShell» → «Буфер обмена» (вкл/выкл, сколько записей хранить). Клавиша — `Mod+Alt+V` (`niri/konshell.kdl`; `Mod+V` в стандартном конфиге niri занят плавающими окнами).

## Погода

`services/Weather.qml` берёт погоду с [Open-Meteo](https://open-meteo.com) — бесплатно, без ключа и регистрации. Город — «Настройки KonShell» → «Часы и календарь» → «Погода» (название, как в поиске карт; переводится в координаты геокодером Open-Meteo). Там же единицы (°C/°F) и частота обновления (по умолчанию раз в 30 минут).

- В панели под часами — сейчас (значок, температура, описание, ощущается как, ветер, влажность) и на 5 дней (максимум, минимум, вероятность осадков от 30 %).
- Виджет для панели «Погода» (`weather`) — значок и температура, добавляется в «Панель» → «Расположение виджетов»; клик открывает прогноз.
- Последний ответ хранится в `~/.cache/konshell/weather.json`: после запуска погода видна сразу, запрос — только если данные устарели. Пока погода нигде не показывалась (панель под часами не открывали, виджета нет), запросов нет; после первого показа — по расписанию до конца сеанса.

## Сеть в панели под часами

Карточка «Сеть» под заметкой (`modules/dashboard/NetworkCard.qml`, данные — `services/NetStats.qml`, работает только пока панель открыта): скорость и пакеты в секунду на приём и отдачу, график за последнюю минуту, объём с включения интерфейса, внутренний IP, шлюз, адрес VPN и внешний IP с городом и провайдером. Клик по адресу копирует его.

- Трафик — по физическому интерфейсу с шлюзом (Wi-Fi или кабель), из `/proc/net/dev`: через него идёт и трафик VPN. VPN — маршрут по умолчанию без шлюза (`tun`, `wg`, `xray` и т. п.).
- Внешний IP знает только внешний сервис: запрос `curl https://ipinfo.io/json` уходит при открытии панели не чаще раза в 5 минут и по кнопке обновления. При включённом VPN это адрес VPN-сервера. Выключить запрос — «Настройки KonShell» → «Часы и календарь» → «Узнавать внешний IP»; карточку целиком — там же, «Сеть».
- Если содержимое панели выше экрана, она прокручивается колесом мыши (над календарём колесо листает месяцы).

## Боковая панель и заметки

`modules/sidebar/` — панель у края экрана: заметки и снимок или запись экрана. Выезжает, когда мышь упирается в край монитора и задерживается там (`sidebar.delay`, по умолчанию 0,25 с): край — правый, левый или оба (`sidebar.edge`). Для этого у краёв каждого монитора стоят прозрачные полоски в 1 пиксель (`konshell-sidebar-edge`, слой Top); углы свободны — там горячий угол niri и кнопки окон. Закрывается кликом мимо, Esc или когда мышь ушла с панели (если в поиске пусто). Всё выключается и настраивается в «Настройки KonShell» → «Боковая панель»; без горячего края — только IPC:

```sh
qs -c konshell ipc call sidebar toggle|open|close
qs -c konshell ipc call sidebar note                     # окно новой заметки
qs -c konshell ipc call sidebar openNote <путь к .md> | closeNote
```

- **Заметки** (`NotesList.qml`) — все `.md` из папки заметок, новые сверху, поиск по имени; дата в начале имени файла в списке не показывается. «+» — новая заметка, значок папки — открыть папку.
- **Окно заметки** (`NoteWindow.qml`) — поверх затемнённого экрана. Новая: заголовок и текст в Markdown, Ctrl+Enter — сохранить в новый файл (как быстрая заметка под часами); закрыли, не сохранив, — черновик остаётся до следующего открытия. Существующая: просмотр с оформлением Markdown (ссылки открываются по клику), «Изменить» — правка исходного текста и сохранение в тот же файл (Ctrl+Enter или Ctrl+S, Esc — отменить правку), открыть во внешнем редакторе (`notes.openCommand`), удалить в корзину (`gio trash`; два нажатия). Последние заметки в панели под часами тоже открываются здесь.
- **Экран** (`CaptureTiles.qml`) — «Скриншот» и «Запись» (см. «Запись экрана и скриншоты»). Из центра управления эти плитки перенесены сюда.

## Меню выключения

`modules/session/` — меню сеанса поверх затемнённого экрана: блокировка, сон, выход из niri, перезагрузка, выключение. Открывается кнопкой питания в шапке центра управления, из «Настройки KonShell» → «Питание» или через IPC. Клавиатура: ←/→ или Tab — выбор, Enter или пробел — действие, Esc — отмена или закрыть. Выход, перезагрузка и выключение срабатывают после обратного отсчёта (по умолчанию 3 с, кольцо вокруг кнопки): повторное нажатие — сразу, Esc или «Отмена» — отменить. Отсчёт и его длительность — в разделе «Питание». Клавиша — `Mod+Shift+E` (`niri/konshell.kdl`, вместо вопроса niri о выходе).

## Часы, календарь и заметки

Панель — до четырёх колонок рядом (300, 300, 340 и 320 px) — широкая и невысокая; по умолчанию: время и календарь · погода и система · плеер и заметка · сеть; размер подстраивается под карточки: ширина — по колонкам, высота — по самой высокой, скрытые и пустые карточки и колонки места не занимают, выше экрана — прокрутка. Состав настраивается: «Настройки KonShell» → «Часы и календарь» → «Карточки и колонки» — какие карточки (время и дата, погода, календарь, система, плеер, заметка, сеть) в какой колонке и в каком порядке; убранная из всех колонок карточка скрыта. Хранится в `dashboard.left`, `dashboard.middle`, `dashboard.right` и `dashboard.extra` (слева направо); карточка, указанная в нескольких колонках, показывается в первой. Разделы, которых не показывать в карточке «Система» (по умолчанию загрузчик: `/boot`, `/boot/efi`, `/efi`), — там же, «Скрытые разделы».

Всё из панели есть и виджетами для бара («Панель» → «Расположение виджетов»): «Часы», «Дата», «Погода», «Монитор системы», «Плеер» (что играет; клик — пауза, колесо — трек, правый клик — панель), «Сеть» (скорость приёма и отдачи), «Заметка» (кнопка новой заметки).

Часы стоят по центру панели (формат — «Настройки KonShell» → «Часы и календарь»). Клик по ним — или правый клик по свободному месту панели (`bar.rightClickDashboard`, выключается в «Панель» → «Вид») — открывает панель `modules/dashboard/`: крупные время и дата, календарь на месяц (стрелки или колесо мыши; первый день недели и номера недель — в настройках), плеер MPRIS (обложка, прогресс с перемоткой по клику, переключение между плеерами) и быстрая заметка. Esc или клик мимо закрывают панель.

Заметки (`services/Notes.qml`) — обычные `.md`-файлы в папке `Notes` внутри папки документов пользователя (`XDG_DOCUMENTS_DIR` из `~/.config/user-dirs.dirs`: `~/Документы/Notes` на русской системе, `~/Documents/Notes` на английской; меняется в разделе «Заметки»). Одна папка для боковой панели, панели под часами и окна заметки. Заголовок, текст в Markdown, Ctrl+Enter или «Сохранить» — и появляется файл `2026-10-18 Заголовок.md` (дату в имени можно выключить; без заголовка имя берётся из первой строки, одинаковые имена получают «(2)», «(3)»). Под полем — последние заметки, клик открывает их в окне заметки (во внешнем редакторе — `notes.openCommand`, например `zeditor`, или программа по умолчанию). Клавиша новой заметки — `Mod+Alt+N` (`niri/konshell.kdl`).

## Окно настроек: разделы

Разделы сгруппированы в боковом меню по категориям (`categories` и `category` в `config/settings-schema.js`): **Внешний вид** — Тема, Интерфейс, Обои, Приложения; **Рабочий стол** — Панель, Часы и календарь, Заметки, Док, Лаунчер, Уведомления, Индикаторы, Центр управления, Музыка; **Система** — Звук и яркость, Клавиатура, Питание, Блокировка. Поиск ищет по всем разделам.

## Док

`modules/dock/` — док внизу каждого монитора, данные — `services/DockApps.qml`. Слева закреплённые приложения (`dock.pinned`, id .desktop-файлов), за разделителем — запущенные незакреплённые. Окно niri сопоставляется с .desktop-файлом по `app_id`.

- Левый клик: не запущено — запустить (значок подпрыгивает, пока не появится окно); запущено — перейти к окну, которое было в фокусе последним; уже в фокусе — к следующему окну приложения. Колесо — окна по очереди.
- Средний клик — новое окно. Правый — меню: список окон, новое окно, закрепить или открепить, сдвинуть левее или правее, закрыть все окна.
- Под значком: точки — число окон (до трёх), полоса акцентного цвета — приложение в фокусе, мигающий красный — окно просит внимания.
- Стиль (`dock.style`): «Прижат к краю» (по умолчанию) — ширина по значкам, по центру, нижняя сторона на краю экрана, верхние углы скруглены, а по бокам вогнутые закругления плавно переходят в край; «Плавающий» — отдельная скруглённая панель с отступом от края. Радиус следует за «Скруглением углов» темы.
- Автоскрытие (`dock.autoHide`, по умолчанию): док выезжает, когда мышь у нижнего края экрана, и всегда виден на пустом рабочем столе. Без автоскрытия niri резервирует под ним место, окна не заходят под док.
- Настройки — «Настройки KonShell» → «Док».

## Трей

`modules/bar/Tray.qml` — виджет `tray`: значки, закреплённые на панели (`tray.pinned`), и кнопка-стрелка, которая открывает остальные во всплывающем окне (`TrayPopup.qml`, компактной сеткой до 6 в ряд, без заголовка). Один значок — `TrayIcon.qml`: левый клик — действие приложения, средний — второе действие, правый — меню самого приложения (`SystemTrayItem.display`, рисует Qt), колесо — прокрутка.

Где показывать значки — «Настройки KonShell» → «Панель» → «Трей»: для каждого «На панели» (`tray.pinned`), «В трее» или «Скрыт» (`tray.hidden`), включая значки закрытых сейчас приложений, если они уже упомянуты в настройках. По умолчанию все значки в трее.

## Курсор

`services/Cursor.qml`: при `cursor.manage` (по умолчанию) оболочка задаёт одну тему и размер курсора (`cursor.theme`, `cursor.size`; «Настройки KonShell» → «Интерфейс» → «Курсор», темы — установленные в `~/.local/share/icons`, `~/.icons`, `/usr/share/icons`):

- `~/.config/niri/konshell-cursor.kdl` — блок `cursor`, подключён в конце `config.kdl` (`include "konshell-cursor.kdl"`, добавляет `scripts/install-theme-hooks.sh`) и перекрывает заданный выше; niri рисует курсор над окнами и оболочкой и передаёт `XCURSOR_THEME`/`XCURSOR_SIZE` запускаемым приложениям;
- `gsettings` `cursor-theme` и `cursor-size` — для GTK и Firefox;
- `~/.local/share/icons/default/index.theme` — тема по умолчанию для XWayland.

Без этого курсор менял размер при переходе между окнами: niri, GTK и XWayland брали его каждый из своего места, а если в конфиге niri указана неустановленная тема — niri рисовал запасной курсор своего размера. Выбранная тема, которой нет, заменяется на Adwaita. Уже открытые приложения подхватят курсор после перезапуска.

## Права администратора (polkit)

`modules/polkit/PolkitDialog.qml` — polkit-агент оболочки: регистрируется при запуске, отдельный агент (polkit-gnome и т. п.) не нужен. Когда программе нужны права администратора (pkexec, монтирование, установка пакетов из графических программ), поверх затемнённого экрана появляется окно с текстом запроса, именем пользователя, полем пароля и идентификатором действия. Enter — подтвердить, Esc — отменить. Проверить: `pkexec true`.

## Окно настроек

«Настройки KonShell» — обычное окно (`modules/settings/`). Открывается из лаунчера (оболочка сама поддерживает `~/.local/share/applications/konshell-settings.desktop`), строкой «Оформление» в центре управления или командой `qs -c konshell ipc call settings open appearance|bar`.

- **Оформление** — тёмная тема, акцент, прозрачность, палитра, обои, какие приложения перекрашивать.
- **Панель** — высота, расположение виджетов и значки трея. Виджеты расставляются перетаскиванием (`modules/settings/LayoutEditor.qml`, карточки — `LayoutCard.qml`): зоны «Слева», «По центру», «Справа» стоят рядом, как на самой панели; карточку можно перенести внутри зоны, в другую зону или в «Скрытые» (крестик на карточке — тоже скрыть, клик по скрытой — вернуть). Хранится в `bar.left`, `bar.center`, `bar.right` (`settings.json`); панель перестраивается сразу. Так же устроен редактор карточек панели под часами.
- **Интерфейс → Курсор** — одна тема и размер курсора для niri, оболочки и приложений (см. «Курсор» ниже).

Каждый раздел — заголовок и строка о том, что в нём (`desc` в `config/settings-schema.js`); параметры собраны в карточки по группам, между параметрами — линии.

- **Уведомления** — «не беспокоить», время показа, сколько всплывающих одновременно, пробное уведомление, очистка истории.
- **Блокировка** — блокировка по простою, выключение экрана, блокировка перед сном, PIN (задать, сменить, убрать), предпросмотр.

Если окно уже открыто на другом рабочем столе, повторное открытие (из лаунчера, центра управления или IPC) переводит на него фокус.

Окно плавающее по правилу в `~/.config/niri/config.kdl` (`app-id="^org\.quickshell$" title="^Настройки KonShell$"`); заголовок Qt отключён (`//@ pragma Env QT_WAYLAND_DISABLE_WINDOWDECORATION=1` в `shell.qml`), закрыть — крестиком в окне или Esc.

## Дизайн

Минималистичный стиль с одним выразительным элементом — мини-картой ленты niri в панели: активный рабочий стол показан полосками колонок, сфокусированная выделена акцентом. Остальное тихое.

- **Цвет**: роли из палитры обоев (`Theme.color`). Акцент `primary` один и отведён фокусу, прогрессу и мини-карте; включённые переключатели — мягкий `primaryContainer`. Состояние никогда не передаётся только цветом: есть галочки, контуры, значки.
- **Шрифт**: Adwaita Sans (как у GTK-приложений). Шкала 1.2 от 13 логических пикселей: `caption` 11, `body` 13, `title` 16, `display` 19; начертания Regular и Medium; табличные цифры для времени и процентов.
- **Форма**: отступы по сетке 4 (`Theme.spacing`); радиус по уровню — панели 12 (как окна niri), элементы 8, круглые только индикаторы. Панели отстоят от края на 6, как `gaps` niri.
- **Прозрачность**: бар и плавающие панели полупрозрачные (`theme.opacity`, 0.75–1, по умолчанию 0.8), под ними niri размывает фон через протокол `ext-background-effect` (`BackgroundEffect.blurRegion` — только под самой панелью). Ниже 0.75 не опускается: приглушённый текст над белым окном перестал бы проходить 4.5:1. Всплывающие уведомления непрозрачные.
- **Глубина**: при прозрачности — размытие и тонкая рамка; при `opacity: 1` у плавающих панелей тень (`widgets/PopupSurface.qml`).
- **Движение**: 120 мс мелкие элементы, 200 мс панели, 300 мс смена палитры; вход с замедлением. `theme.reduceMotion: true` в `settings.json` делает все переходы мгновенными.
- **Клавиатура**: все элементы центра управления и истории уведомлений доступны по Tab, Enter и пробелу; ползунки — стрелками; рамка фокуса — `widgets/FocusRing.qml`.

## Блокировка экрана

`modules/lock/LockScreen.qml`, `services/Lock.qml`. Блокировка по протоколу ext-session-lock: если оболочка упадёт, niri оставит экран заблокированным, а перезапущенная оболочка (метка `~/.local/state/konshell/locked`) сразу заблокирует его снова.

- Разблокировка: PIN (если задан) или системный пароль через PAM (`/etc/pam.d/swaylock` → стек `login`). Неверный PIN проверяется без PAM и не тратит попытки `pam_faillock`; после 5 неверных PIN подряд PIN отключается на 5 минут.
- PIN хранится в `~/.local/state/konshell/lock-pin` (права 600) как солёный md5 — четыре цифры перебираются мгновенно, это защита только от случайного взгляда.
- Блокировка по простою (`lock.idleTimeout`, 300 с), выключение мониторов на заблокированном экране (`lock.screenOffTimeout`, 60 с), блокировка перед сном (`lock.beforeSleep`): оболочка держит задержку сна у systemd и отпускает её, только когда niri подтвердил блокировку.
- `Super+Alt+L` или IPC:

```sh
qs -c konshell ipc call lock lock
qs -c konshell ipc call lock preview | closePreview   # вид без настоящей блокировки
qs -c konshell ipc call lock setPin <PIN> | clearPin
```

Если экран не разблокируется: перейдите в консоль (`Ctrl+Alt+F3`), войдите и выполните `pkill -x qs; qs -c konshell &` с `WAYLAND_DISPLAY=wayland-1` — новая оболочка возьмёт блокировку на себя; либо запустите `swaylock` в той же сессии и введите пароль.

## Режим обзора и ресурсы

- При входе в обзор niri закрываются центр управления, история уведомлений и лаунчер: они забирают клавиатуру и мешали бы управлять обзором.
- Обои — один слой на монитор (в заднике niri), декодируются под размер экрана.
- Замеры (1920×1080, масштаб 1.25, 2026-10-19, со всеми модулями): процессор в простое ~0,07 %, ~0,6 пробуждения главного потока в секунду, отрисовка в простое не идёт; память ~370–380 МБ, из них ~210 МБ — сам Quickshell с Qt и драйвером. Многократное открытие и закрытие панелей память не наращивает.
- Плавность всплывающих окон (2026-10-21, замер интервалов между кадрами анимации — все 15–17 мс, ровные 60 FPS):
  - окна после первого открытия не удаляются, а скрываются (`widgets/PopupLoader.qml`, `keepLoaded`): повторное открытие — показ готового окна без построения содержимого;
  - анимация начинается, когда окно уже на экране (5 кадров у нового окна, 3 у готового), а содержимое с самого начала рисуется с прозрачностью 1 %: иначе тексты, значки и эффекты создавались в первый видимый кадр посреди анимации — провал 40–70 мс.
- Помощники оболочки (`gdbus monitor`, `systemd-inhibit`, `wl-paste`, `wf-recorder`) — прямые потомки и запускаются через `setpriv --pdeathsig`: умирают вместе с оболочкой. Раньше `gdbus` за промежуточным `sh` переживал каждую перезагрузку конфигурации и копился (находилось 20 сирот по ~8 МБ).
- Почему так мало пробуждений:
  - `QT_WAYLAND_FRAME_CALLBACK_TIMEOUT` в `shell.qml`. Невидимым поверхностям (обои под окнами) niri шлёт сигнал кадра примерно раз в секунду; Qt по умолчанию ждёт его 100 мс, объявляет окно скрытым, а с приходом сигнала перерисовывает целиком. Без этой строки — кадр в секунду и ~8 пробуждений в секунду впустую (0,37 % процессора).
  - Иконки (`widgets/SymbolIcon.qml`) выравниваются по пикселям по сигналам сдвига своих предков, без таймеров.
  - Опрос системы (`SystemStats`, `NetStats`), позиция плеера и график сети работают, только пока их видно.
- Память подробнее (2026-10-20): RSS ~390 МБ, но реальная доля оболочки (PSS) ~255 МБ — остальное общие с другими программами библиотеки (драйвер Mesa 45 МБ и LLVM 77 МБ грузит любая программа с OpenGL: niri, Xwayland, kitty, Zed). Своей памяти ~180 МБ: Qt, граф сцены, драйвер; мусора в JavaScript почти нет — сборка (`ipc call shell collectGarbage`) ничего не освобождает. Рисует видеокарта (i915), не программный llvmpipe. Обои декодируются под размер экрана, скрытый слой после перехода освобождается.
- Запуск: ~0,7–0,9 с до панели на экране и ответа на IPC.
- Помощники оболочки: `systemd-inhibit` (блокировка перед сном), `gdbus monitor` (сигнал о сне), два `wl-paste --watch` (история буфера обмена) — вместе ~30 МБ, процессор в простое не тратят.
- Проверить самому: `pid=$(pgrep -x qs); grep voluntary /proc/$pid/status` дважды с паузой — разница за 30 с должна быть в пределах нескольких десятков.

## Обои и цветовая тема

Обои рисует сама оболочка — один слой `konshell-wallpaper` на монитор, в заднике niri. Рабочие столы прозрачные, поэтому обои видны сквозь них и стоят на месте: в обзоре и при переходе на стол выше или ниже под каждым столом нет своей копии. Обе настройки — в `niri/konshell.kdl`:

```kdl
layout {
    background-color "transparent"
}

layer-rule {
    match namespace="^konshell-wallpaper$"
    place-within-backdrop true
}
```

Обои, тёмную или светлую тему и вариант палитры можно выбрать в центре управления: строка «Оформление». Путь к обоям хранится в `wallpaper.path` в `settings.json`; если он пуст, берётся первая картинка из `~/Pictures/Wallpapers` (или `wallpaper.directory`). Смена пути, правка `settings.json` или замена файла по тому же пути перекрашивают оболочку без перезапуска.

Как строится палитра:
1. `services/ColorScheme` запускает `scripts/generate-palette.sh` (через 300 мс после последнего изменения, не чаще).
2. Скрипт вызывает `matugen image … --dry-run -j hex --source-color-index N`. Ключ кэша (путь, время изменения, схема, контраст) совпал с записанным — matugen не запускается. Формат, который matugen не читает (AVIF), переводится в PNG через ffmpeg. В бесцветных обоях (ч/б, серые) matugen не находит цвета и подставил бы синий `#4285f4`; вместо этого строится «Нейтральная» палитра от среднего цвета картинки (или «Монохром», если выбран он), а на странице «Оформление» появляется пояснение.
3. Роли Material You переводятся в токены `config/color.js`: поверхности, текст, акценты, состояния, успех/предупреждение/ошибка. Все пары «текст — фон» подтягиваются до WCAG AA (4.5:1 для текста, 3:1 для иконок и границ).
4. Результат для обоих режимов пишется в `palette.json` (атомарно), `Theme` перечитывает его и плавно меняет цвета.

Акцент (`theme.accent`): `wallpaper` (по умолчанию) — исходный цвет обоев с тем же оттенком и насыщенностью, светлота подгоняется к читаемости (тёмная тема — OKLCH L 0.62–0.88, светлая — 0.40–0.62); `material` — более мягкий primary схемы. У бесцветных обоев акцент всегда из схемы.

Настройки в `settings.json`, раздел `theme`: `mode` (`dark`/`light`, независимо от обоев), `scheme` (вариант matugen: `tonal-spot`, `vibrant`, `expressive`, `neutral`, `fidelity`, `content`, `monochrome`, `rainbow`, `fruit-salad`), `contrast` (−1…1), `source` (`wallpaper` или `color` с `seedColor`), `sourceColorIndex`, `accent`, `opacity`, `animate`, `reduceMotion`.

### Перекраска приложений

`services/ThemeExport.qml` при смене палитры или режима заполняет шаблоны из `templates/` и пишет отдельные файлы цветов. Файл перезаписывается и приложение перезагружается, только если содержимое изменилось.

| Приложение | Файл цветов | Как применяется |
|---|---|---|
| GTK 4 (libadwaita) и GTK 3 | `~/.config/gtk-{3,4}.0/konshell-colors.css` | новые окна; GTK 3 — только с темой adw-gtk3 (`sudo pacman -S adw-gtk-theme`) |
| Qt 6 (через qt6ct) | `~/.config/qt6ct/colors/KonShell.conf` | сразу у запущенных (qt6ct следит за `qt6ct.conf`); приложениям нужна переменная `QT_QPA_PLATFORMTHEME=qt6ct` — её добавляет скрипт в блок `environment` конфига niri, действует для приложений, запущенных после перезахода в сеанс |
| kitty (и fish в нём) | `~/.config/kitty/konshell-colors.conf` | сразу, `SIGUSR1` |
| niri (рамки окон) | `~/.config/niri/konshell-colors.kdl` | сразу, `niri msg action load-config-file` |
| Firefox (Pywalfox) | `~/.cache/wal/colors.json` | сразу, `pywalfox update`; нужно расширение Pywalfox |
| Zed | `~/.config/zed/themes/konshell.json` | темы KonShell Dark и Light, Zed выбирает по системному режиму |

Плюс `gsettings … color-scheme` (`prefer-dark` / `prefer-light`) — его видят порталы, браузеры и сайты.

Подключить файлы цветов к конфигам приложений (один раз; повторный запуск ничего не дублирует, рядом сохраняются копии `*.konshell-bak`):

```sh
scripts/install-theme-hooks.sh              # добавить include/@import, выбрать темы KonShell в Zed, схему KonShell в qt6ct
scripts/install-theme-hooks.sh --uninstall  # убрать
```

Какие приложения перекрашивать — `theme.exports` в `settings.json` или «Настройки KonShell» → «Приложения». Шаблоны поддерживают `{{token}}`, `{{dark.token}}` / `{{light.token}}`, `{{token|alpha:0.5}}`, `{{token|strip}}`, `{{name|json}}`, `{{token|qt}}` / `{{token|qt:0.5}}` (Qt: `#aarrggbb`); цвета терминала — `{{term0}}` … `{{term15}}`.

### Диагностика

- `qs -c konshell ipc call theme status` — состояние генерации, последняя ошибка, источник палитры, `usingFallback` (true — палитры из обоев ещё нет), исправления контраста.
- Сообщения в логе Quickshell начинаются с `color-scheme:`, `theme:` и `wallpaper:`.
- Ошибки и поведение:

  | Ситуация | Что происходит |
  |---|---|
  | нет matugen | ошибка «matugen не найден», повтор через 2, 4, 8 … 60 с; палитра прежняя |
  | файла обоев нет | ошибка «Файл обоев недоступен», палитра и картинка прежние |
  | формат не читается | попытка через ffmpeg, иначе ошибка; палитра прежняя |
  | `palette.json` повреждён | предупреждение `theme:`, остаётся последняя разобранная или резервная палитра |

- Проверить скрипт генерации вручную: `scripts/generate-palette.sh image <картинка> tonal-spot 0 0 ""`.
- Проверить контраст: `node tools/check-palette.js <картинка>` или `node tools/check-palette.js --file`.
- Пересобрать резервную палитру после изменения `color.js`: `node tools/check-palette.js --fallback "#6b7fd7"` и вставить вывод в `config/fallback-palette.js`.
